# Automatic Firestore rules deployment

The backend repository (`backend.unlim8ted.com`) owns the Firestore rules in `rules/database.rules`. Its `.github/workflows/firebase-rules.yml` deploys that file to the `unlim8ted-db` Firebase project whenever the rules or workflow change on `main`. You can also run the workflow manually. This uses the Firebase CLI only; it does not deploy Firebase Functions.

Add the GitHub Actions secret `FIREBASE_SERVICE_ACCOUNT_UNLIM8TED_DB` to the **backend repository**: GitHub > `Unlim8ted-Studios/backend.unlim8ted.com` > Settings > Secrets and variables > Actions > New repository secret. Its value is the complete Firebase service account JSON for `unlim8ted-db`, including the braces. If you still have the Firebase Admin SDK JSON file used for the main repository, you can use its contents. GitHub cannot reveal the main repository's saved secret. If the file is lost, create a new key in Firebase Console > Project settings > Service accounts > Firebase Admin SDK > Generate new private key. Keep that file private and never commit it. An organization secret shared with both repositories is another option.

The backend's `firebase.json` points to `rules/database.rules`; the website's root `firebase.json` points to the same file through its submodule for local tests. The workflow deploys `firestore:rules` only. It leaves hosting, indexes, and other Firebase services alone.

After pushing the backend commit, check the Actions result and compare the active rules in Firebase Console with the committed backend rules. If the initial workflow run fails because the secret was absent, add the secret and rerun the job. Rules deployment needs valid credentials; none were available for a live deployment in this workspace.

The service account also needs permission to inspect enabled APIs. If the job fails with `Permission denied to get service [firestore.googleapis.com]`, open Google Cloud Console > IAM & Admin > IAM for project `unlim8ted-db`, find the service account named in the JSON, and grant **Service Usage Viewer** (`roles/serviceusage.serviceUsageViewer`). The account also needs **Firebase Rules Admin** (`roles/firebaserules.admin`) to publish rules. Then rerun the failed GitHub Actions job. Keep the downloaded Admin SDK JSON outside the web repository.
