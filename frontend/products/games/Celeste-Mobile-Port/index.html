The mobile climb

Celeste without turning it into a different game.

The project keeps Celeste, Everest, mods, and the core game runtime together inside a shared WebAssembly environment. The native wrappers handle the parts that actually belong to the phone.

Controls built for glass

Drag, resize, reposition, save layouts, switch between a joystick and arrows, enable 8-way snapping, and interact with Celeste's menus directly through touch.

Mobile-aware camera

Optional camera centering helps keep the player away from fingers while respecting room boundaries, cutscenes, and transitions.

Saves that stay saved

IndexedDB-backed persistence, explicit runtime restore, save export/import, file management, and mod persistence.

Native haptics

Celeste's existing rumble events are routed through the mobile bridge to native haptic feedback, configurable from the normal Options menu.

CelesteNet integration

Join official, custom, saved, LAN, and discovered servers from a mobile-first multiplayer interface.

Everest comes with you

The runtime supports Everest, persistent mods, a mod browser, third-party Mod Options, and independent mobile modules instead of baking every mobile feature into one giant patch.

Build maps on the mountain

BetterMapEditor provides an in-game, touch-capable environment for creating projects, chapters, rooms, solids, spawns, strawberries, springs, spikes, and real Celeste map binaries.

Architecture

One runtime. Thin wrappers.

Celeste is not being rewritten as an Android or iOS game. Nearly all game logic stays inside the same threaded WebAssembly environment.

01
Android and iOS provide platform-specific services such as haptics, storage, lifecycle handling, and native hosting.
02
Celeste + Everest run together in the shared threaded .NET WebAssembly runtime.
03
Mobile behavior is divided into independent Everest modules with clearly separated responsibilities.

About the Port
Platform wrappers

Same mountain. Different host.

Android and iOS are intended to share CelesteRuntime and CelesteMobileMods. Only the native platform layer changes.

Android + GeckoView

The primary implementation today. GeckoView hosts the threaded runtime with SharedArrayBuffer, WebAssembly threads, cross-origin isolation, local asset serving, native haptics, storage, and Android lifecycle support.

Functional

iOS

The iOS wrapper is intended to host the same shared runtime while implementing equivalent Apple-platform storage, haptics, file access, persistence, lifecycle, and multiplayer services.
